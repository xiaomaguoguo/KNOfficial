## 常见问题 (FAQ)

### 真的安全吗？你们能访问我的数据吗？

**绝对不能。** 这不是营销废话——从技术上讲，我们根本不可能访问您的数据。原因如下：

- 您的文件使用浏览器的 [File API](https://developer.mozilla.org/en-US/docs/Web/API/File_API) 读取，将其保存在您设备的内存中
- 所有处理都发生在浏览器的 JavaScript 运行时中
- 我们的服务器只提供静态 HTML/JS/WASM 文件——它从未接收您的数据库
- 您可以通过打开浏览器的“网络”标签页并观察上传（没有上传）来验证这一点

**专业提示**：尝试在关闭 Wi-Fi 的情况下使用它。它仍然完美运行，因为不需要上传任何内容。

### 文件大小限制是多少？

我们要支持最大 **500MB** 的数据库。存在此限制是因为浏览器有内存限制，而不是因为服务器限制（请记住，处理过程中不涉及服务器）。

为了提供背景信息，500MB 足以容纳：
- 典型表格中的数百万行
- 大多数移动应用数据库
- 开发和测试数据库
- 中小型生产数据集

### 支持哪些文件格式？

我们支持所有标准的 SQLite 格式：
- `.db` (最常见)
- `.sqlite`
- `.sqlite3`
- `.db3`

如果您的文件是由 SQLite（或与 SQLite 兼容的工具，如 Room, Core Data 或 Electron 应用）创建的，它就可以工作。

### 它能离线工作吗？

**是的！** 首次访问后，该工具会被您的浏览器缓存并完全离线工作。这使得它非常适合：
- 气隙环境
- 安全的企业网络
- 没有互联网的旅行
- 无法承担数据泄露风险的情况

虽然该工具足够强大，足以处理生产数据，但我们建议：

## 技术深度剖析：SQLite WASM 如何工作（针对好奇者）

如果您对技术细节感兴趣，以下是幕后发生的事情：

### 编译过程
1. 官方 SQLite C 源代码使用 [Emscripten](https://emscripten.org/) 编译为 WebAssembly
2. 这生成了一个浏览器可以直接执行的 `.wasm` 二进制文件
3. JavaScript 绑定为 Web 开发人员提供了熟悉的 API

### 内存管理
- 您的数据库文件作为 `ArrayBuffer`（原始二进制数据）读取
- SQLite 的 `sqlite3_deserialize()` 函数将其加载到 WASM 内存中
- 查询在此内存表示上运行
- 结果被编组回 JavaScript 对象

### 性能优化
- **无网络 I/O**：消除了传统 Web 应用中最大的瓶颈
- **共享内存**：现代浏览器支持 SharedArrayBuffer 以实现更快的数据传输
- **编译查询**：SQLite 的查询规划器在 WASM 中的工作方式与在原生代码中相同

### 安全保障
- **同源策略**：其他网站无法访问您的数据库
- **无服务器端状态**：我们实际上没有基础设施来存储您的数据
- **浏览器沙盒**：即使我们的代码有漏洞，您的数据也会保留在浏览器的受保护内存中
