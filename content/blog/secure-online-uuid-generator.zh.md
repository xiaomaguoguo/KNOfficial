## 服务器端生成器的问题

大多数在线工具的工作方式如下：
1.  你请求一个 UUID。
2.  请求发送到他们的服务器（后端）。
3.  他们的服务器生成 ID。
4.  ID 被发送回给你。

这种往返不仅增加了延迟，还留下了“书面痕迹”。理论上，服务器可以记录它发出的每个 ID。如果这些 ID 是可预测的，或者如果服务器的随机数生成器 (RNG) 很弱，你系统的安全性可能会受到损害。

## 解决方案：`crypto.randomUUID()`

Knothing 采取了不同的方法。我们使用内置于你浏览器中的现代 **Web Crypto API**。

具体来说，我们使用 `crypto.randomUUID()`。此函数使用你的操作系统提供的 **加密安全伪随机数生成器 (CSPRNG)**。

### 为什么 Knothing 更好：
1.  **零网络请求**：UUID 是在你设备的 CPU 上创建的。没有任何数据发送到我们的服务器。
2.  **加密强度高**：它不仅仅是 `Math.random()`（这对密钥来说是不安全的）。它是行业标准的安全级别。
3.  **支持离线**：因为它是一个 PWA，你可以断开网络连接，仍然生成数百万个 ID。

## 常见问题解答

### 什么是 UUID v4？
版本 4 UUID 是使用随机数生成的通用唯一标识符。它看起来像这样：`xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx`。`4` 表示版本，`y` 是 `8`、`9`、`A` 或 `B` 之一。

### 它防碰撞吗？
是的。碰撞（生成两个完全相同的 UUID）的概率极低。你需要多年每秒生成数十亿个 UUID 才有极小的机会出现重复。对于几乎所有的数据库主键用例来说，它都是安全的。

### 我可以将其用于 SQL 主键吗？
当然。UUID 广泛用作 PostgreSQL、MySQL 和 NoSQL 数据库（如 MongoDB）中的主键。它们允许你在应用程序代码（或客户端）中生成 ID，而无需等待数据库分配自增整数。
