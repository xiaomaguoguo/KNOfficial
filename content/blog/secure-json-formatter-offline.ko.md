# 무작위 JSON 포맷터에 민감한 데이터를 붙여넣지 마세요

## 여러분이 아마도 무시하고 있는 보안 악몽

상상해 보세요: 새벽 2시에 API 응답을 디버깅하고 있습니다. JSON은 엉망입니다. 들여쓰기도 없고, 모든 것이 한 줄에 있습니다. 전체 페이로드(사용자 이메일, API 토큰, 세션 ID 포함)를 복사하여 Google에서 찾은 첫 번째 "JSON 포맷터"에 붙여넣습니다.

**불편한 진실은 이렇습니다**: 여러분은 방금 회사 기밀 데이터를 전혀 모르는 무작위 서버로 전송했습니다.

- 그 서버의 소유자는 누구입니까?
- 그들이 데이터를 기록하고 있습니까?
- 제3자에게 판매되고 있습니까?
- 데이터 유출로 이어질 수 있습니까?

여러분은 모릅니다. 그리고 그것은 무서운 일입니다.

## 해결책: 100% 클라이언트 측 JSON 처리

**KNothing의 JSON 포맷터**는 이 문제를 완전히 해결합니다. 방법은 다음과 같습니다:

### 제로 서버 통신

우리의 JSON 포맷터는 **완전히 브라우저 내에서** 실행됩니다. JSON을 붙여넣을 때:

1. 데이터는 브라우저 메모리에 유지됩니다
2. 네이티브 JavaScript(`JSON.parse()` 및 `JSON.stringify()`)를 사용합니다
3. **네트워크 요청 없음**
4. 데이터가 서버에 닿지 않음

믿지 못하시겠습니까? 브라우저의 개발자 도구(F12)를 열고 "네트워크"(Network) 탭으로 이동하여 확인해 보세요. JSON을 포맷할 때 **0개의 요청**을 보게 될 것입니다.

### 오프라인 작동 (PWA)

모든 것이 클라이언트 측에서 실행되므로 말 그대로 다음이 가능합니다:

1. 페이지를 한 번 로드
2. **인터넷 연결 끊기**
3. JSON 포맷 계속하기

한번 해보세요. 진심입니다. Wi-Fi를 끄더라도 PWA(Progressive Web Apps) 기술 덕분에 완벽하게 작동합니다.

## 기술적 심층 분석: 작동 원리

기술에 호기심이 많은 분들을 위해 내부에서 일어나는 일은 다음과 같습니다:

```javascript
// 1. JSON 파싱 (구문 검증)
const parsed = JSON.parse(yourJsonString)

// 2. 2칸 들여쓰기로 뷰티파이
const beautified = JSON.stringify(parsed, null, 2)

// 3. 축소 (모든 공백 제거)
const minified = JSON.stringify(parsed)
```

이 모든 것은 **브라우저의 JavaScript 엔진**에서 발생합니다. 서버 없음. 데이터베이스 없음. 로그 없음.

## 정말 중요한 기능

### 🔍 즉각적인 검증

형식이 잘못된 JSON을 붙여넣고 **즉각적인 피드백**을 받으세요:

- 구문 오류 강조 표시
- 디버깅을 위한 줄 번호
- 명확한 오류 메시지 (모호한 서버 오류 아님)

우리가 잡아내는 일반적인 문제:
- 후행 쉼표 (JSON에서 유효하지 않음)
- 따옴표 없는 키
- 큰따옴표 대신 작은따옴표 사용
- 괄호 또는 중괄호 누락

### 📦 프로덕션용 축소

API 페이로드 또는 구성 파일을 위해 JSON을 압축해야 합니까?

- 모든 공백 제거
- 파일 크기 약 40-60% 감소
- 프로덕션 환경에 적합

### ✨ 사람이 읽기 쉽게 (Beautify)

JSON을 다시 읽기 쉽게 만드세요:

- 2칸 들여쓰기 (업계 표준)
- 적절한 줄 바꿈
- 컬러 구문 강조
- 원클릭 복사

### 🚀 파일 크기 제한 없음

1MB 또는 5MB로 제한하는 많은 온라인 도구와 달리, 당사의 포맷터는 **브라우저 RAM**에 의해서만 제한됩니다. 다음으로 테스트했습니다:

- 50MB+ JSON 파일
- 깊게 중첩된 객체 (100+ 레벨)
- 100,000개 이상의 항목이 있는 배열

```json
{"userId":123,"email":"user@example.com","token":"sk_live_abc123","permissions":["read","write"]}
```

이것을 무작위 웹사이트에 붙여넣으시겠습니까? KNothing을 사용하면 토큰 유출 걱정 없이 안전하게 포맷할 수 있습니다.

### 2. 구성 파일 관리

`package.json`, `tsconfig.json` 또는 AWS 구성 파일로 작업하십니까? 인프라 세부 정보를 노출하지 않고 포맷하세요.

### 3. 데이터 마이그레이션

PII(개인 식별 정보)가 포함된 데이터베이스 내보내기 또는 API 덤프를 정리하시나요? 로컬에 보관하세요.

## 자주 묻는 질문 (FAQ)

### Q: 정말 안전한가요?

**A:** 네. 브라우저의 개발자 도구(F12) → 네트워크 탭을 엽니다. JSON을 붙여넣고 포맷하세요. **네트워크 요청이 없음**을 볼 수 있습니다. 코드도 검사를 위해 공개되어 있습니다 — 우클릭 → 페이지 소스 보기.

### Q: 대용량 파일을 처리하나요?

**A:** 네. 최대 100MB 파일을 테스트했습니다. 유일한 제한은 브라우저의 사용 가능한 RAM입니다. 참조:
- 작은 파일 (<1MB): 즉시
- 중간 파일 (1-10MB): 1-2초
- 큰 파일 (10-50MB): 3-5초

### Q: 모바일은요?

**A:** 모바일 브라우저(Chrome, Safari, Firefox)에서 완벽하게 작동합니다. 오프라인 액세스를 위해 PWA를 홈 화면에 설치할 수도 있습니다.

### Q: 포맷된 JSON을 공유해야 한다면요?

**A:** "복사" 버튼을 사용하여 포맷된 출력을 복사한 다음 선호하는 방법(이메일, Slack 등)을 통해 공유하세요. 당사는 귀하의 데이터를 저장하거나 전송하지 않습니다.

## 개인정보 보호 보장

우리는 세 가지 약속을 합니다:

1. **추적 없음**: Google Analytics 없음, 쿠키 없음, 핑거프린팅 없음
2. **저장 없음**: JSON은 저장되지 않습니다 (localStorage에도 없음)
3. **네트워크 없음**: 서버 요청 제로 (개발자 도구에서 확인)

귀하의 데이터는 **귀하의 데이터**입니다. 이상입니다.
